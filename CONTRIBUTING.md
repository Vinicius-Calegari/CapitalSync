# Contribuindo

1. Crie uma branch curta a partir de `main`.
2. Faça mudanças pequenas e verificáveis.
3. Use commits semânticos: `feat:`, `fix:`, `test:`, `docs:`, `refactor:`, `ci:` ou `chore:`.
4. Execute `dotnet build` e `dotnet test` antes de abrir PR.
5. Não inclua API keys, `.env`, dados pessoais ou artefatos locais.
6. No PR, descreva problema, solução, como validar e riscos conhecidos.
